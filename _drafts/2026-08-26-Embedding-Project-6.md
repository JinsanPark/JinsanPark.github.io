## 지난 시간

저번 시간에 백터를 재사용한다고 했었죠.<br>
우리가 매번 "경제"를 검색할때 마다, API를 호출해서, 요청 보내고, 받고 하면 느리겠죠? 실제로 측정에서도 API 호출 시간이 제일 길었고요.

이유는 간단합니다. 일단 api를 호출안해도 되고, 또 호출 안하니깐 돈이 안들죠.

## 그러면 어떻게?

일단 2가지 방법을 고려해봤습니다.<br>
첫번째는 램처럼 애플리케이션 단에다가 저장해버리는거고, 두번째는 하드디스크에 저장하듯, DB에다가 저장해버리는거에요.<br>
장단점도 비슷합니다.

애플리케이션 메모리에다가 저장하면 빨라요. DB를 드나들지 않고 바로 찾아주니깐요. 근데, 램이랑 똑같이 서버 재부팅 하면 다 사라집니다. DB에다가 저장하면 재부팅해도 그대로지만, DB왔다갔다 하는 시간이 걸리고요.

그래서 저는 두가지 다 써보려고 합니다.

`메모리 -> 미스 -> DB -> 미스 -> Voyage API`

이런 방식으로 구현해 볼까 합니다.

캐시 히트 와 미스란 뭘까요? 캐시 히트(찾음), 캐시 미스(못찾음) 위에서 봤듯 히트가 많을 수록 성능이 빨라지겠죠. 단계가 줄어드니깐요.

## 정규화

`ai 투자 == AI 투자 == Ai 투자 == ai투자 == AI투자 == Ai투자`
우리가 보기에는 다 똑같잖아요? 근데 컴퓨터는 각각 다른 걸로 봅니다.
그래서 해줘야 할건 정규화라고 똑같이 다듬어 줄건데, 
 
`NFC 정규화 → 앞뒤 공백 제거 → 연속 공백 한 칸으로 → 소문자`
이런 순서로 할겁니다.

## DB 벡터 캐시 테이블 구조

| 컬럼 | 용도 |
|---|---|
| id | PK (대리키) |
| 정규화된 검색어 | 캐시 키 |
| 모델 이름 | 캐시 키 |
| 벡터 | 캐시 값 |
| 생성 시각 | 운영/디버깅용 |

검색어, 모델에 복합 유니크 제약 이유, PK 아닌 이유 설명해주기.


## 구현

어떻게 할까 머리를 굴려 보다가, 플래그를 세워서 캐시 히트/미스로 하려고 했는데, AI한테 뺀찌 먹었습니다. 더 좋은게 있다네요. Optional<> 이라고.


이렇게, 1단계 DB에서 구현이 끝났습니다. 자주 쓰는 검색어들 미리 선별해서 넣어둬도 괜찮지 않을까 생각이 드네요.


## 측정

| 구분 | 중앙값 | p95 |
|---|---|---|
| 캐시 없음 (지난 글, 300건) | 225.3ms | 233.8 ms |
| 캐시 히트 | 28.2 ms | 44.8 ms |
| 캐시 미스 | 289.6 ms | 333.4 ms |


캐시 히트가 되면 많이 빨리집니다. 조건이 좀 많긴 합니다. 전건이 캐시 히트가 났고, HTML 자체가 아무것도 없기도 하고, 받는 데이터 자체도 10건이 전부라 응답 자체가 2 ~ 5kb밖에 되지 않고, 거기다가 바로 옆에 랩탑한테 보내는 로컬 네트워크 환경이고, 나중에 JS나 이것저것 프론트에 넣고 좀 멀리 있는 서버에 호스팅 하고 그러면 더 느려질 수 있겠죠.

근데 이상하지 않나요? 캐시 미스나니깐, 더 느려지네요? 일이 늘어나서 느려질 수 있다고 느끼긴 했는데, 막상 거진 100ms 가량이 늘어나니깐, 뭔가 잘못된거 같아서 API 시간 측정을 다시 해봤습니다.
550회 API 호출 시간 중앙값이 197.1ms 정도 나왔습니다. 저번 시간에 300건 측정했을때 대략 197.8 ms 나왔는데, 사실상 같다고 봐도 무방하겠죠.
